# 数据与因果协议审计

> 独立数据审计代理（重新从 10.2 GB 归档流式重算，覆盖全部 251 电芯）

## 1 泄漏：确认且严重

| 检验 | 结果 |
|---|---|
| 电芯内 Spearman(逐循环 `capacity_charge`, 同期 C/5 容量) | **中位 0.9951**，IQR [0.983, 0.998]，min 0.701；98.6% 电芯 >0.95；0% 为负 |
| `median(capacity_charge / 同期容量)` | **0.300 = 协议 DoD** |
| 区间均值 Ah vs 收尾 RPT 的 SOH | Pearson 中位 **0.993**，R² 0.985 |
| 弹性 `dlog Ah / dlog Q` | 中位 **2.49**（Ah 下降快于容量，还携带阻抗/倍率衰减） |

**机制确认**：`capacity_charge = DoD × 当前容量`，是**交付容量测量**，不是 BMS 运行计数器。

**且它随年龄漂移**：电芯内稳健 CV 中位 0.468；线性时间趋势 R² 中位 0.819；滞后 1 自相关 0.965；
**100% 电芯单调下降**。它不是协议常数。

## 2 归档中不存在指令 Ah

cycling JSON 只有 7 个键：`capacity_charge`、`capacity_discharge`、`QV_charge`、`QV_discharge`、
`start_stop_time`、`time_series_charge`、`time_series_discharge`。**每一个 Ah 都是测量值。**
→ **exposure-only 的 Ah 计数器无法构造**；名义 `N × DoD × Q_rated` 在同一工况内是循环数的
仿射函数，不增加独立信息。

## 3 三分类

| 类别 | 特征 |
|---|---|
| **EXPOSURE-ONLY** | 累计循环数；日历天；循环起止时间戳（节奏）；周块边界/计数；放电电流设定值（每工况恒定） |
| **CAPACITY-DERIVED** | 累计充/放 Ah；逐循环 Ah 滑动均值/趋势；**循环时长**（r=0.930）；**充电时长**（r=0.888）；放电采样点数（r=0.988） |
| **RPT-HEALTH** | SOH、`soh_last`、`soh0`、斜率 |

**静置时长**：全电芯恒为 **5.00 s**（CV=0.000）→ 合法但**无信息**，已弃用。

## 4 可用性时序

验证顺序（全部电芯）：`c_i^start < c_i^stop < d_i^start < d_i^stop < c_{i+1}^start`。

| 量 | 可用时刻 |
|---|---|
| 循环 i 已开始 | `c_i^start` |
| 循环 i 的充电 Ah | `c_i^stop`（**循环开始时不可知**） |
| 循环时长 | `d_i^stop` |
| RPT 的 SOH | `R_k^stop`，即开始后约 **18.57 h**（实测中位） |

**五条静默前视路径**已在 G0/G1 中全部消除：未完成放电的累计 Ah；周块 stop 在块内使用；
RPT 在其 18.6 h 完成前被使用；标签归一化用全程最大值（改为**首检归一化**）；全历史特征缩放。

## 5 EOL 与删失

- **251/251 观测到 80% 越界；右删失 0**；RPT 0 处越界 0；最后一条 RPT 处越界 1。
- 战役远超 EOL：末次观测 SOH 中位 0.472，min 0.131。
- 区间宽度（全部 251）：日历 **8.01 天**、物理循环 **138**、累计充电 Ah **13.50**。
- 定义一致：251/251 用 C/5 字段（C/2 回退从未触发）。
- 1 颗电芯（G2C2）在简单越界与持续越界规则下不同（RPT 19 vs 21）。

## 6 两处协议缺陷（已修复，见 `G0_build_cohort.py`）

**缺陷 1**：工况 20–29 的每颗电芯，RPT 记录第 5 条是 `'[]'`，旧加载器丢整颗电芯 →
**10 个完整工况从本程序所有历史派生表消失**。修复后 208→**250** 电芯、53→**63** 工况。

**缺陷 2**：`mean_DoD_pct` 对 21/53 工况不可复现（比值 0.068–0.559）。归档测量自洽，
**可疑的是表**。已改用实测 DoD。

## 7 停机与缺失

`on_test` 占日历跨度中位 **0.857**；周块内几乎无静置（循环时间/on_test = 0.998）。
92.8% 的 RPT 时间落在 cycling 间隙内；但**仅 59.9% 的间隙时间被 RPT 窗口覆盖**。
→ 仅凭 cycling 文件**无法**区分「静置」与「缺记录」；交叉 RPT 流可解释排定的多数，
残余约 40% 应为 **UNVERIFIED**。实务结论：**停机是日程协变量，不是健康协变量。**

## 8 跨数据集 EOL 可比性

| 数据集 | 结论 |
|---|---|
| CALCE CS2_21 | C/2 放电、**无 C/5 参考测试** → EOL 定义与 ISU 不同；`SOH_80(C/2) ≠ SOH_80(C/5)` |
| NASA PCoE | .mat 载荷 **UNVERIFIED**；常用 0.7×额定 ≠ ISU 的 0.80 |
| Bayreuth | `fXXXX_bol/eol` 是 EIS 谱不是容量检查；内部 System 字段与文件名不一致；checkup 倍率文件缺失 → **UNVERIFIED** |
| Severson | 旁边 README 明确是**占位符**（数据未上传）→ 出处 **UNVERIFIED** |
| UConn | `README_uconn.txt` 是 Cloudflare 挑战页；参考容量基准 **UNVERIFIED** |

**把这些标签直接汇总会把「EOL 定义」与「数据集身份」混为一谈——这正是跨数据集泛化主张必须避免的混淆。**
