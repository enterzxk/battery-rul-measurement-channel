## A0 Codex 裁决摘要（thread `01a1c478-615e-7933-910d-81d402f25660`）

**GO（有条件）**：允许在剩余预算内跑一次完整回放。
**NO-GO**：不得把 E1 审计当作"可实现收益"的证明，也不得声称双向时间杠杆是区别于
decision-aware VoI 的新机制。

Codex 的三条实质裁定：

1. **I6 作为上界是成立的**（每颗电芯上 oracle ≤ 任何可行选择器的损失），
   但 oracle 利用了"哪个子集恰好让实现损失最小"这一在线不可得的信息，所以
   `headroom > margin` 只说明"没有排除存在可用时序价值"，**不说明存在**。
   → 必须新增 **Δ_CF（按工况交叉拟合的可实现增益）**作为主结果。
2. **Candidate 与 decision-aware VoI 目前不可分辨。** 且标准 VoI 并不必然是"越晚越多"，
   Fauriat & Zio 2020 已做由期望决策收益驱动的序列检查排程。
   → Candidate 只能作为"一个预先指定的时序启发式"接受检验，不能作为机制贡献。
3. **E1 的 oracle 少了一个动作约束**：`R = exp(q_τ)` 未强制 `R ≥ T`。
   → 回放中所有臂**与 oracle 一致地**使用 `R = max(T, exp(q_τ(log M | history)))`。

## A1 采集信息契约（非预知性）

策略在第 k 步（已购 k 次）可用的信息**仅限**：

1. 第 0 天信息：`t_0`、`soh(t_0)`、工况应力描述量（DoD / 充电倍率 / 放电倍率）；
2. 当前时间与已购观测的（时刻, SOH）序列；
3. **检查日历**（该电芯在 `(t_0, T]` 内已排定的参考测试时刻）——这是运维方在
   第 0 天就已知的计划表；
4. 剩余预算 N − k；
5. 在训练工况上拟合的模型。

**禁止**：未来容量、未来 EOL、完整轨迹、未购时点的容量、未来观测计数之外的信息。
未来时点的 SOH **只能通过外推预测**得到（见 A3 的外推规则），且该预测必须同时提供给
所有需要它的臂。

**等 N 可执行性**：N 是硬约束，每个臂恰好买 N 次；不存在"提前停"的臂。

## A2 评价总体（跨所有臂、N、T 固定）

对给定 `(T, N)`：`cohort(T, N) = {cells : T < L, cond ∈ 应力表, x[0] = 0, |avail| ≥ 3}`。
`avail` 要求 `≥ 3` 而非 `≥ N`，故**同一 T 下所有 N 用同一批电芯**。外层留出工况后，
训练集与测试集的电芯集合分别固定。

未使用的电芯（`L ≤ T`）是**幸存者总体**，见原协议 §10.3。
条件 20–29 无可用电芯（`E2_datahazard.json`），覆盖缺口如实报告。

## A3 外推规则（VoI 与 Candidate 共用，预注册）

给定已购观测 `(x_p, s_p)`（按时间升序），对任意未来时点 `t > x_p[-1]`：

```
ŝoh(t) = clip( s_p[-1] + slope_ols(x_p, s_p) · (t − x_p[-1]),  0.05, 1.05 )
```

`slope_ols` 为已购观测的最小二乘斜率；若 `|x_p| < 2` 则 `slope = 0`。
**这条规则对所有臂相同**，故外推误差不构成臂间差异。

## A4 策略集（全部非预知、等 N）

| 臂 | 规则 | 用数据选点 |
|---|---|---|
| `FixedEven` | 取 `avail` 上最接近等间隔的 N 个 | 否 |
| `FixedLate` | `avail` 最后 N 个 | 否 |
| `FixedEarly` | `avail` 最前 N 个 | 否 |
| `Random` | 从 `avail` 均匀抽 N（20 个预注册种子，报均值与其自身区间） | 否 |
| `VoI` | 逐步一步前瞻：对每个候选 t 用 A3 外推补全历史 → 用**期望损失模型**预测损失 → 取最小者；买后按实际观测更新 | 是（决策感知） |
| `Candidate` | 逐步：`score(t) = (1 − ŝoh(t)/soh_first) · (T − t)/T`，取最大者 | 是（启发式） |

**关于 Candidate 的诚实声明（冻结时写下，不得事后补充）**：
`score(t)` 的乘积形式**按构造**就是倒 U，所以"内部最优"这一预测由构造保证，
**不构成对机制的检验**。因此本轮：
- Candidate 只作为"预先指定的时序启发式"接受检验；
- 其倒 U 预测记为 **BY CONSTRUCTION，不是发现**；
- 原协议 §5 的"可证伪预测 1"**作废**（不能证伪一个构造出来的性质）；
- "窄重叠单元优势更大"保留为可检验的预测 2。

## A5 期望损失模型（VoI 专用）

在**训练工况**上用内层 5 折（按工况分组）得到折外 `R`，据此算出折外实现损失
`loss = max(0, M − R) + ratio · max(0, R − M)`，再以该损失为目标、以子集特征为输入
拟合 `HGBRegressor(max_iter=300, lr=0.05, random_state=0)`。
外层测试工况的任何信息都不进入该模型的拟合。

## A6 主分析设定（**由 Codex 指定，不是从策略表现里挑的**）

> `T = 63`，`N = 2`，`c_f/c_w = 5`，`c_insp = 1`

**主统计量 = Δ_CF（按工况交叉拟合的可实现增益）**

```
Δ_CF = mean over held-out conditions g of mean over cells i in g of
        [ J_i(fixed, selected WITHOUT g) − J_i(policy, learned WITHOUT g) ]
```

以**天**为单位报告，同时报告相对最强固定策略的比例。
原协议的 10% 是**相对**门槛，保持不变。

**判定**：`Δ_CF` 的单侧 95% 下界 > 门槛（绝对量：0.10 × 该设定下最强固定策略的 J）
→ 记为支持"时序选择有价值"。区间跨门槛 → INCONCLUSIVE，不得写成等价或无效。

**"最强固定策略"**：在**训练工况内**从 `{FixedEven, FixedLate, FixedEarly, Random}` 中
按 J 选出，不得使用测试工况信息。这是 Codex 第 6 条要求。

**Δ_CF 的两种增益都要报**：
- `Δ_CF(vs fixed)` — 主结果；
- `Δ_CF(vs VoI)` — 用于判定 Candidate 是否区别于 VoI。

## A7 端点与敏感性（Codex 第 9 条）

- 主目标 `M = (L+U)/2`（原协议已注册），**必须**附区间敏感性。
- 区间敏感性：对每颗电芯，把 `z ∈ [L, U]` 上的配对损失差在 `z = L`、`z = U` 以及
  任一臂的更换时刻落入区间处取值，得到该电芯的配对差上下界；按同一工况权重聚合。
- 另报 SUSTAINED 端点规则（`E2`：仅 1/208 电芯改变）作为额外敏感性，**不做**任何
  依赖结果的剔除。

## A8 不确定性与多重性

- 单位 = 工况。按工况做配对 bootstrap（10 000 次），报单侧 95% 下界。
- 子集、同工况内的电芯、相互重叠的 LOCO 训练集**一律不当作独立重复**。
- 主设定之外的 53 个设定**全部报告**，但标为 secondary，不做"最好的那个"式挑选。
- 额外确认性主张需预注册的多重性规则；本轮回放不产生此类主张。
