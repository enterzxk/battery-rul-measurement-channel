## 0. 一页结论

**在这个数据规模下还能被可靠回答的问题，只有一类：估计量落在组内、以「分解 / 比例 / 曲线 / 界」而非「显著性」作答、且预期效应 ≥ 2×MDE 的问题。**

凡是需要「工况总体」的问题——包括本项目刚判死的那个——无论方法多好都答不了。这不是方法的失败，是设计的失败：工况级 n=11，MDE 是基线 MAE 的 **19.3%**；任何小于 19% 的效应，在这份数据上**不可能**被检出（要 5% 需 **122 个工况**）。

三个候选方向（都不是方法，都是问题）：

| 方向 | 一句话研究问题 | 统计单位 / n | 预期效应 vs MDE | 判定 |
|---|---|---|---|---|
| **D1 传感器还是标签** | 这条通道的信息上限，卡在测量侧（信噪比）还是标签侧（状态→剩余寿命的映射）？ | 查询 17,130（簇：64 电芯 / 11 工况） | 方差比 344:1；误差比 3.1–4.3× ≫ 19.3% | **强**（解释性） |
| **D2 标签预算** | 跨工况迁移到底需要「120 个工况」还是「16 个目标标签」？ | 查询 2,813（簇：11 工况，配对） | 效应 49.2% ≫ MDE 19.3%；p=0.010 | **最强**（实用性，n=11 已显著） |
| **D3 基准有效性** | 当所有模型都离可达上界 3 倍时，LOGO 的特征集排序测的是信息量还是可迁移性？ | 查询 2,813（簇：11 工况） | 误差比 3×；差值界 0.22 循环 = 基线 3.3% | 中（批判性，风险高） |

三者的共同点：**都不需要新数据、不需要新模型、不需要 100+ 工况**；都能在 ≤1 天 CPU 内判定；失败时都会留下一个可用的界或一个明确的排除。

## 1. 先算功效，再提方向

### 1.1 三级单位的真实 MDE

主对比（A_curve vs A_curve+C_ecm，LOGO，配对差 `d = |err_ecm| − |err_curve|`）在三种推断单位下的簇稳健标准误【实测，`preds.csv` 运行 20261107-203233】：

| 推断单位 | 名义 n | 簇数 G | 簇稳健 SE | MDE80（循环单位） | 占基线 MAE 6.61 的 % | 结论 |
|---|---:|---:|---:|---:|---:|---|
| 查询（忽略聚类） | 2,813 | — | 0.076 | 0.21 | **3.2%** | **无效**：低估 SE 2.94× |
| 电芯簇 | 2,813 | 64 | 0.225 | 0.64 | **9.7%** | 只比工况簇好 2 倍 |
| 工况簇 | 2,813 | 11 | 0.410 | 1.28 | **19.3%** | 只够检出 d ≥ 0.94 |

折算成标准化 d（以工况级 ΔMAE 的 SD = 1.301 为单位）：**n = 11 → d = 0.94**；等效 n = 21.4 → d = 0.64；若错误地把 2,813 条查询当独立样本 → d = 0.05（这个数本身就是错误的证据）。

簇内相关与设计效应【实测】：

| 量 | 按电芯聚类 | 按工况聚类 |
|---|---:|---:|
| ICC（对配对差 d） | 0.169 | 0.101 |
| 平均簇大小 n₀ | 43.9 | 252.0 |
| design effect `1+(n₀−1)·ICC` | **8.26** | **26.25** |
| 等效 n | **340** | 107 |

工况级点估计：11 个工况的 ΔMAE 均值 −0.553，sd 1.301，t = −1.410，**p = 0.189**，Cohen d = −0.425【实测】——与 A3 的 p = 0.192 / d = 0.421 一致【文档：`AUDIT_AGENT3.md` §4.2】。

### 1.2 三个反直觉的结论

**结论一：查询级 n = 2,813 只买到 2 倍，不是 16 倍。**
从 11 个工况簇换到 64 个电芯簇，MDE 从 19.3% 降到 9.7%（2.0×）；再想换到 2,813 个独立查询是不可能的，因为 deff = 8.26，等效 n 只有 340。**「我有几千条查询」是一个错觉。**

**结论二：64 个电芯不是 64 个独立样本。**
电芯簇的 MDE 是 9.7%，只比工况簇好 2 倍；而电芯内部还嵌着 11 个工况，ICC = 0.414【文档：`AUDIT_AGENT3.md` §4.1】把等效 n 压到 21.4。**电芯级只能回答「这个现象存在吗」（d ≥ 0.64），不能回答「它有多大」。**

**结论三：工况级 19.3% 与任务书的 17.1% 同源。**
两者是同一量（`MDE_d × sd / 基线`）在不同运行/种子下的取值，差 1.3 pp，不影响任何结论。要检出 5% 的相对效应需要 **122 个工况**【实测，解析式 `n = (2.802·sd/Δ)²`】——与任务书的「120 个」一致。

### 1.3 四条设计规则（本文的筛选器）

> 一个研究问题要在这份数据上活下来，必须同时满足：

- **R1｜估计量必须落在组内。** 问题的答案不能依赖「工况之间的差异」，只能依赖「同一工况内的差异」或「同一电芯内的差异」。跨工况的差异需要 122 个工况才能估准。
- **R2｜预期效应 ≥ 2×MDE。** 以工况为推断单位时 ≥ 37%，以电芯簇为推断单位时 ≥ 19%。低于此的问题，即使为真也检不出——这正是本项目的死因（5% vs 19.3%）。
- **R3｜必须允许以「界 / 曲线 / 比例 / 分解」作答。** 「不显著」不是答案，「排除了大于 X 的效应」才是答案。R3 把一个失败的检验变成一个有信息量的界。
- **R4｜不做总体推断，只做复现。** 不问「在所有工况上平均如何」，只问「在 k 个工况中有几个满足 P」。k/K 是复现计数，不需要工况总体。

**三条被这四条规则直接判死的**：跨工况增量、跨数据集 RUL 验证、任何「再跑一次说不定显著」。

## 2. 三个候选方向

### D1｜传感器还是标签：通道的信息上限卡在哪一侧？

#### ① 研究问题

**这条非循环测量通道的信息上限，是被测量侧的信噪比卡住的，还是被标签侧「状态 → 剩余寿命」的映射卡住的？**

#### ② 统计单位、数量、功效

- **单位**：查询。UConn 有 17,130 条波形（2,813 个 (电芯, RPT) 查询 × 6 个脉冲位），簇为 64 电芯 / 11 工况。
- **估计量是分解，不是假设检验**，因此不需要「拒绝零假设」的功效，只需要区间够窄：

| 量 | 点估计 | 簇 bootstrap 95% CI | 判读 |
|---|---:|---|---|
| 工作点（SOC × 方向）占波形方差 | **99.71%** | [99.60%, 99.78%] | 通道几乎全部被工作点占据 |
| 工作点之外的部分占总方差 | 0.29% | [0.22%, 0.40%] | 老化 + 个体 + 噪声全在这里 |
| 全寿命老化漂移 / 残差 SD（波形形状） | **0.380** | [0.318, 0.407] | 整个寿命只移动 0.38 个残差 SD |
| 波形形状：老化漂移 / 单次测量噪声 | **1.33** | — | 全寿命漂移只有噪声的 1.3 倍 |
| DCIR 标量：老化漂移 / 残差 SD | **4.33** | — | 同一通道，换成标量后强 11 倍 |
| DCIR 标量：老化漂移 / 单次测量噪声 | **17.4** | — | 老化是可测的 |
| 组内可达误差（k→∞，仅用 SOH） | **2.11–2.32** | — | 标签侧上界 |
| 最好的跨工况模型（A_curve） | 6.53 | — | 离上界 **2.9×** |

- **功效论证**：这些对比是 344:1（方差比）和 3.1–4.3×（误差比），远超 R2 要求的 2×MDE（19.3%）。**不需要 p 值**。
- **唯一需要检验的一项**（若必须做成检验）：老化方向与工况子空间的主夹角 = **4.74°**，而组内打乱 SOH 的置换零分布是 12.5° ± 3.2°（200 次置换，0 次低于观测值），**p < 0.005**【实测】。含义：老化把波形推的方向，与工况把波形推的方向，在测量空间里近乎平行。

**关键的反直觉结果**：通道测老化是**够用**的（DCIR 的 SNR 17.4），真正卡住的是标签——组内用 SOH 就能做到 MAE 2.1，而任何跨工况模型都在 6.5–9.1。**「传感器没问题，是剩余寿命这个标签本身被工况锁死了」**（EOL 的组间 η² = 0.942【文档：`IDEAS_AGENT2.md` F5】）。

#### ③ 为什么现有工作没做

- `LITERATURE_MATRIX.md` 77 条中，EIS 的**测量精度与重复性**有专文（L76 Kasper 2025，矩阵标 **L3 仅摘要**，本文转引），**DRT 峰位的 SOC 依赖**有专文（L17 Khan 2024，矩阵标 **L1**，A1 精读，本文转引），但**没有一条把「工作点 / 噪声 / 老化」三者的方差预算作为 RUL 失败的机理解释**。
- `GAP_ANALYSIS.md` 的 G1–G6 六类 gap 中，G3 是「可辨识性」，G6 是「覆盖率与统计单位」，**均不覆盖方差归因**。
- 领域惯例是报**预测误差**，误差低就说通道有用；没有人先问「这个通道里有多少是信号」。这与 P5（功效审计应在实验前完成）是同一个毛病的前置版本。

#### ④ 最小可验证实验（≤1 天 CPU）

**已完成的 pilot（本文作者，约 15 min CPU）**：主成分分解 + 方差归因 + 置换零分布 + 簇 bootstrap。结果见上表。

**正式版还需三件事（合计 ≤4 h CPU）**：
1. **Bayreuth 复现**（1,649 次拟合，23 工况）：同样的方差预算，检验 99.7% 这个数是 UConn 协议特有的还是时域弛豫的共性。
2. **变差函数线性性检验**（10 min）：lag-1 到 lag-5 的 semivariance 是否线性。若线性，lag-1 才代表噪声；若不平，噪声估计偏大，SNR 会被低估。
3. **用修正后的 ECM 参数重做**（2 h）：当前 `.cache/desc_*.npz` 是 **legacy 拟合**（tau1 有 15,056/17,130 行 = 88% 钉在下界 1.0），不能用于任何机制结论；必须用 `ip+1` 起点 + 秒单位 + 60 s 上界重拟合。

#### ⑤ 如果失败，会得到什么

- **若老化占比 > 50% 且 SNR > 10**（即通道信息量充足）：那么「通道没用」是错的，失败在标签侧——直接指向 D2/D3，且你拿到一个可发表的「传感器没问题、基准有问题」结论。
- **若工作点占比 < 90%**：那么「通道被工作点淹没」这个解释不成立，必须另找原因（例如模型容量、标签口径），这本身就是一条明确的排除，省掉后续所有基于该解释的推理。
- **若置换检验 p > 0.05**：老化方向与工况方向在测量空间里**正交**，那么「不可分离」的机理解释被否证，D3 的立论需要重写——这是一条提前发现的致命问题，比写完论文再发现便宜得多。

### D2｜标签预算：跨工况迁移需要 120 个工况，还是 16 个标签？

#### ① 研究问题

**把跨工况 RUL 从「零样本迁移到未见工况」改成「k 个目标工况标签的少样本校准」之后，需要多少标签才能逼近组内可达上界？**

#### ② 统计单位、数量、功效

- **单位**：查询（2,813），簇为 11 个工况；比较是**配对**的（同一 k、同一批查询、同一随机子集）。
- **实测学习曲线**（1-NN on SOH；标签取自**目标工况的其他电芯**，被预测电芯完全留出——这是最严格的「新电芯、已知工况」设定）【实测】：

| k（目标工况标签数） | MAE（剩余 RPT） | 对照 |
|---:|---:|---|
| 4 | 6.24 | |
| 8 | 4.23 | |
| **16** | **3.33** | 已优于 LOGO 全模型 6.53 |
| 32 | 3.01 | |
| 64 | 2.89 | 逼近组内上界 2.1 |
| 0（LOGO，跨工况） | 9.15（仅 SOH）/ 6.53（A_curve 54 维） | 【文档：`AUDIT_AGENT3.md` §4.4 + `e1_v2_fixed_results.md`】 |

- **配对检验（n = 11 工况）**：k=16 的少样本校准 vs LOGO 全模型 A_curve，逐工况 ΔMAE 均值 **+3.21 循环**，sd 3.38，t = 3.15，**p = 0.010**，95% CI **[+0.94, +5.48]**，**10/11 个工况更优**，相对改善 **49.2%**【实测】。
- **功效论证**：效应 49.2% ≫ MDE 19.3%，所以在 n = 11 上**已经显著**。这不是「勉强显著」，而是 2.5 倍于最小可检出效应。同一份数据、同一个 n=11，换一个效应量 5% 的问题就是 p=0.19——**问题选得对不对，比样本量重要**。

#### ③ 为什么现有工作没做

- `LITERATURE_MATRIX.md` 77 条中**没有一条**以「目标工况需要多少标签」为研究问题；「few-shot / 少样本 / 微调样本量」在矩阵与 `GAP_ANALYSIS.md` 中均未出现（检索式与阅读等级见矩阵；此判断的效力限于该矩阵，不等于文献中不存在）。
- A2 的 **I4（无标签跨数据集可迁移性）方向相反**：它问「没有标签能做什么」，本文问「最少要几个标签」。两者互补，不重叠。
- 领域惯例是 LOGO / LOCO 二分：LOGO 回答「换工况」，LOCO 回答「同工况换电芯」。**「同工况换电芯 + k 个标签」这个格子是空的**，而它恰恰是部署时唯一存在的格子（新电芯进厂，工况已知，能测几次 RPT）。

#### ④ 最小可验证实验（≤1 天 CPU）

**已完成的 pilot（约 25 min CPU）**：严格跨电芯 1-NN 学习曲线 + 逐工况配对检验。结果见上表。

**正式版还需四件事（合计 ≤6 h CPU）**：
1. **换真模型**：1-NN 是无参数的保守基线；正式版用 HistGradientBoosting / Ridge，**k 的选取必须嵌套**（内层从训练工况选 k，不许用测试集选 k——这是本项目 R5 的教训）。
2. **k=0 锚点**：必须同时报 LOGO，否则读者不知道 3.33 是「校准的功劳」还是「SOH 的功劳」。
3. **两种标签来源分开报**：同一电芯的其他 RPT（k=8 时 3.03）vs 同工况其他电芯（k=8 时 4.23）。前者是「跟踪」，后者才是「迁移」。
4. **Bayreuth 复现**（48 电芯 / 23 工况）：检验 16 这个数是不是 UConn 的工况结构特有的。

#### ⑤ 如果失败，会得到什么

- **若 k 增到目标工况 50% 的数据仍到不了 3.3**：那么「迁移成本是映射问题」不成立，是**特征问题** → 回到 D1/D3，且你得到了「至少需要 X 个标签」的**下界**，这本身是实验设计依据。
- **若 k=16 的优势在嵌套选 k 后消失**：那么 pilot 的 3.33 是「用测试集挑 k」的乐观偏差——这是一条**必须在正式版之前**排除的伪影，与 P1（拟合窗伪影）同类，提前发现就是净收益。
- **若 Bayreuth 上 16 不成立（需要 100+）**：那么「k 个标签」是 UConn 的协议红利，不是普适结论——这会把主张从「普适配方」降级为「单数据集观察」，但**仍然是一个可发表的负向边界**，且直接给出「为什么 UConn 特殊」的下一个问题。

### D3｜基准有效性：LOGO 排序测的是信息量还是可迁移性？

#### ① 研究问题

**当所有模型都离组内可达上界 3 倍以上时，LOGO 基准给出的特征集排序，测的是特征的信息量，还是特征的可迁移性？**

#### ② 统计单位、数量、功效

- **单位**：查询（2,813），簇为 11 工况。
- **核心三个数**【实测 + 文档】：
  - 组内可达上界（只给 SOH，k→∞，留一）：**MAE 2.11–2.32**
  - 最好的跨工况模型（A_curve 54 维）：**6.53**
  - 最差的（rpt only）：**13.50**【文档：`AUDIT_AGENT3.md` §4.4】
  - → 所有模型离上界 **2.9×–5.9×**。
- **排序反转的直接证据**【实测】：LOGO 下「SOH only 9.15」远差于「A_curve 6.53」，看起来 54 维曲线带来了巨大信息。但在组内 k=32 的设定下：

| 特征集 | 组内 k=32 MAE | 与 [SOH] 的差 |
|---|---:|---|
| [SOH] | **3.63** | — |
| [SOH + 30 维脉冲描述量] | 3.91 | **+0.28**，95% CI **[−0.77, +0.22]** |

  → 脉冲描述量在**信息量口径**下的增量上界是 **0.22 循环 = 基线的 3.3%**，比工况级 MDE（19.3%）小 **6 倍**。**LOGO 的 6.53 vs 9.15 是 40% 的差距，组内的差距是 <4%——排序测的是可迁移性。**
- **功效论证**：误差比 3× ≫ 19.3%，无需额外功效；差值上界 0.22 是一个**界**，按 R3 直接可报，不依赖显著性。

#### ③ 为什么现有工作没做

- `GAP_ANALYSIS.md` G1 已指出：RUL 上没有「同回归器、同查询、只换通道」的隔离对照（L13 Jones 2022 做过，矩阵标 **L1**，A1 精读，本文转引；但目标是下一循环容量、且无留出工况）。**但 G1 说的是「对照缺失」，本文问的是「对照的绝对刻度是否有效」——两件事。**
- **没有人报告「组内可达误差下界」。** G6 覆盖覆盖率与统计单位，不覆盖可达性。
- A2 的 **I3（可达差距闭合率）** 最接近，但口径不同：I3 的下界来自**组间寿命分布**（跨工况），用途是把 5% 的增益重述为「闭合了 X% 的可达差距」；`DECISION_LOG.md` 已将其降级，理由是「在 CI 已跨零的前提下用闭合率重述增益，有给零结果化妆的风险」【文档】。**本文的下界来自组内 oracle，用途不是重述增益，而是检验基准本身是否具备分辨力**——这是它没有被降级的原因。

#### ④ 最小可验证实验（≤1 天 CPU）

**已完成的 pilot（约 20 min CPU）**：组内 oracle（留一、按 SOH 匹配）+ 组内 k-shot 特征集对比。

**正式版还需三件事（合计 ≤6 h CPU）**：
1. **对每个特征集算组内 oracle**，不只是 SOH。若 A_curve 的组内 oracle 也是 2.1，则「54 维曲线无额外信息」成立；若它是 1.2，则曲线确有信息，只是迁移不掉。
2. **oracle 的 ε 敏感性曲线**：ε ∈ {0.25, 0.5, 1.0, 2.0}，本 pilot 已给出 2.32 / 2.16 / 2.11 / 2.29，**平坦**，说明上界对 ε 不敏感（这是好消息）。
3. **反事实检查**：把 oracle 的参考集限制为「同工况、不同电芯」，确认 2.1 不是同电芯泄漏（D2 的 k=16 严格版 3.33 已部分回答）。

#### ⑤ 如果失败，会得到什么

- **若组内 oracle 也很高（≥6）**：模型已在上界附近，「基准无效」不成立，反而说明通道确实没信息——与 D1 互为交叉验证，两条独立路径指向同一结论，比单条更有说服力。
- **若组内 oracle 只有 1.0–1.5（比 SOH 的 2.1 还低）**：说明存在某个未被利用的信息源，「模型容量不足」成为主因，方向应立即转向建模而不是基准批判——这是一条会**改变整个项目走向**的早期信号。
- **若排序在组内口径下不变**（A_curve 仍显著优于 SOH）：那么 LOGO 基准是有效的，本文的核心主张被否证；但你会得到一张「排序在两种口径下一致」的表，这本身是对领域基准的一次**正面验证**，也是可发表的（且比批判性结论更容易过审）。

### A.1 三级单位的 MDE 与 deff

```python
import numpy as np, pandas as pd
from scipy import stats
df = pd.read_csv("code/results/20261107-203233_e1_reproduce_full_table/preds.csv")
e_c = np.abs(df.pred_A_curve_logo - df.y_true).values
e_e = np.abs(df["pred_A_curve+C_ecm_logo"] - df.y_true).values
d   = e_e - e_c
def cluster_se(y, cl):
    cl = np.asarray(cl); G = np.unique(cl); N = len(y)
    s = np.array([y[cl == g].sum() for g in G])
    return np.sqrt(np.sum((s - s.mean())**2) * (len(G)/(len(G)-1)) / N**2), len(G)
for name, cl in [("cell", df.cell_id), ("condition", df.group_id)]:
    se, G = cluster_se(d, cl)
    tc, tp = stats.t.ppf(.975, G-1), stats.t.ppf(.80, G-1)
    print(name, G, "SE=%.3f MDE=%.3f (%.1f%%)" % (se, (tc+tp)*se, 100*(tc+tp)*se/e_c.mean()))
def icc(y, cl):
    cl = np.asarray(cl); gs = [y[cl==g] for g in np.unique(cl)]
    k, n, m = len(gs), len(y), y.mean()
    ssb = sum(len(g)*(g.mean()-m)**2 for g in gs)
    ssw = sum(((g-g.mean())**2).sum() for g in gs)
    msb, msw = ssb/(k-1), ssw/(n-k)
    n0 = (n - sum(len(g)**2 for g in gs)/n)/(k-1)
    deff = 1 + (n0-1)*(msb-msw)/(msb+(n0-1)*msw)
    return deff, n/deff
print("deff/n_eff by cell:", icc(d, df.cell_id))
```

```python
def oracle(df, eps, min_n=2):
    errs = []
    for g, sub in df.groupby("group_id"):
        f, y = sub.soh.values, sub.y_true.values
        for i in range(len(sub)):
            m = np.abs(f - f[i]) <= eps; m[i] = False
```

### A.5 严格跨电芯 k-shot 学习曲线

```python
def strict_kshot(df, k, reps=40, rng=np.random.default_rng(2)):
    errs = []
    for g, sub in df.groupby("group_id"):
        for tc in sub.cell_id.unique():
            test, pool = sub[sub.cell_id==tc], sub[sub.cell_id!=tc]
            if len(pool) < k or len(test) < 5: continue
            f, y = pool.soh.values, pool.y_true.values
            ft, yt = test.soh.values, test.y_true.values
            for _ in range(reps):
                ii = rng.choice(len(pool), k, replace=False)
                j = np.abs(ft[:,None] - f[ii][None,:]).argmin(1)
                errs.append(np.abs(yt - y[ii][j]).mean())
    return np.mean(errs)
```

### A.6 组内 k-shot 特征集对比

```python
def ridge_kshot(df, X, k, lam=1.0, reps=40, rng=np.random.default_rng(5)):
    errs, per = [], {}
    for g, sub in df.groupby("group_id"):
        n = len(sub)
        if k >= n: continue
        Z = np.column_stack([sub.soh.values, X[sub.index]])
        Zs = (Z - Z.mean(0)) / (Z.std(0) + 1e-9)
        y = sub.y_true.values; v = []
        for _ in range(reps):
            ii = rng.choice(n, k, replace=False); m = np.ones(n, bool); m[ii] = False
            A = np.c_[np.ones(k), Zs[ii]]
            b = np.linalg.solve(A.T@A + lam*np.eye(A.shape[1]), A.T@y[ii])
            e = np.abs(y[m] - np.c_[np.ones(m.sum()), Zs[m]]@b).mean()
            v.append(e); errs.append(e)
        per[int(g)] = np.mean(v)
    return float(np.mean(errs)), per
# X0 = np.zeros((len(df),0))  vs  Xd = 30-d descriptor matrix (6 pulse slots x 5 desc)
```
